## Advisor decisions (D195–D197, verbatim intent)

### D195 (B2-1 + B2-2, shared root) — reconciliation becomes CONVERGENCE on the rail's current state; events and checkout ids are triggers, never data carriers.
1. One convergence function `syncPlanFromRail(workspaceId, …)` in the billing module: read the customer's CURRENT subscription state from the rail (`getSubscriptionState` — the D168 interface member; complete it on both clients if T5 shipped it partially), then UPSERT `workspace_plans` to exactly that — active pro ⇒ pro + ids; no active subscription ⇒ free, ids nulled.
2. `reconcileCheckout` narrows to trigger + binding proof: verify the checkout succeeded and belongs to the caller's workspace (D176 guard unchanged), then call `syncPlanFromRail`. Never writes a plan from the checkout object. → B2-1 dies (a spent bookmark after revocation converges to free).
3. The webhook is a doorbell: signature validation + D169 consumed set as the trigger filter + ACK posture unchanged, but the payload is never applied — the handler calls `syncPlanFromRail`. → B2-2 dies (re-delivered/reordered `active` re-reads the present revoked state → free). One rail read per webhook is inside the 10s/2s budget.
4. The last race (two concurrent syncs interleaving) serialized with `pg_advisory_xact_lock(hashtext(workspace_id))` around read-rail→write inside `syncPlanFromRail`. No ordering column, no event-id table, no migration 0006.
5. Fake fidelity (S2.3 L3 / D194): the fake gains a settable subscription state so revoke/re-deliver sequences are drivable; it yields what the rail yields, no-subscription ⇒ free.

### D196 (B3-1) — the workspace-state entry's freshness is its own contract, decoupled from the token cache.
Every `Workspace()` call checks the state entry's own expiry; expired/missing state refreshes synchronously under `lookupTimeout` with per-workspace SINGLEFLIGHT — exactly one caller refreshes, concurrent callers for that workspace serve the existing stale entry (fail-static shape applied to staleness). D164(d) asymmetry untouched: fail-open remains ONLY the Postgres-error/never-fetched narrowing; with Postgres healthy the 35s bound now holds for every key. **D164(c) is amended on the record to this wording.**

### D197 (B4-1) — mechanical guard, blessed with two pins.
Primary: the write side (override upsert) serializes with the SAME `pg_advisory_xact_lock(hashtext(workspace_id))` primitive F6 introduces (one serialization idiom in the codebase).
