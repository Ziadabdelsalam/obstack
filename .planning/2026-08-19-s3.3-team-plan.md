### D163 — Plan/quota model
- **The plan catalog lives in Postgres** (`plans`, seeded) — the ONE definition both runtimes read; no quota constant in Go or TS.
- **Absent `workspace_plans` row = free.** Resolution everywhere: `JOIN plans p ON p.id = COALESCE(wp.plan_id, 'free')`. No signup change, no backfill.
- **M3 plans: free (50k events/mo, 7-day retention, $0) and pro (1M events/mo, 30-day retention, $49/mo)** — the numbers the mock suite and landing already display, adopted as the catalog of record; **the adoption rides the user notice** (they become real pricing copy).
- Retention renders from `plans.retention_days` with the D105 disclaimer verbatim. **Explain-run quota column REFUSED now** — S3.5 adds it in 0006 when it has a consumer.
- Over-quota, stated once: `SUM(spans+logs)` over `period_start >= date_trunc('month', now() AT TIME ZONE 'UTC')` `>= p.event_quota`. Billing period = calendar month, UTC.

### D164 — Workspace-state cache + auth seam (T2)
- (a) **Two maps, one package, one TTL, one staleness story.** In `keystore`: token map `hash → {workspaceID, keyID, expiresAt}` (negative = empty workspaceID, exactly today's semantics, all eight red proofs preserved); workspace map `workspaceID → {overQuota bool, prices *pricing.Table, expiresAt}`. Same 30s constant.
- (b) **Auth seam:** `type Identity struct { WorkspaceID, KeyID string }`; `auth.Resolver.Workspace(token) (Identity, error)`; `Authenticator.Workspace(authorization) (Identity, error)`; context helpers become `ContextWithIdentity`/`IdentityFromContext`. Wire contract and D6 posture byte-unchanged — identity is server-internal.
- (c) **Workspace-state refresh piggybacks on token resolution:** missing/expired state entry refreshes in the same auth call (two statements under `lookupTimeout`: the D163 over-quota SELECT + the overrides SELECT). `Store.State(workspaceID) State` is a **non-blocking cache read** — consume/write paths never wait on Postgres.
- (d) **Failure asymmetry, on the record:** auth stays **fail-static** (D98 verbatim); quota/overrides are **fail-open** — Postgres down or never fetched ⇒ not-over-quota, base prices. Our outage must never sample away a paying customer's traces; auth fail-open would be a security hole, quota fail-open is our commercial risk. One line in the package doc.
- (e) **One pgxpool.** main.go (T4) creates the pool; `keystore.New(pool)` replaces dial-in-Open; `metering.New(pool, …)` shares it.
- (f) **D155 memory restatement (package doc):** token entries widen by one short string; 10k bound still protects the negative class; positives bounded by real `api_keys` rows. The workspace map is **not attacker-growable** (entries only for workspaces a valid key resolved); size driver is override rows; **T7's create action caps overrides at 100 per workspace** (app-side, stated in the form error) — worst case ~tens of MB; no second bound constant.

### D165 — Sampling contract (T4)
- **Rate: 10%, named constant `quotaSampleRate` in `receive`, no env, no per-plan rate.** UI copy stays qualitative.
- **Verdict function, pinned: FNV-1a 64 over the 16 raw trace-id bytes; keep iff `h % 10 == 0`.** Deterministic and seedless — one verdict across requests and replicas. Applied in the shared consume path (`receive.go`), both transports inherit.
- A sampled-out trace drops **whole**: spans and trace-id'd log records. Trace-less logs draw per-record at the same rate from an injectable RNG (deterministic in tests). Drops counted per record into `obstack_ingest_dropped_total{reason="quota"}` AND the accumulator's `dropped_quota`; survivors meter as normal accepted events.

### D166 — Metering accumulator/flush (T3)
- In-memory per-`(workspaceID, keyID)` cells: accepted, dropped_decode, dropped_unsupported, dropped_quota, last_event_at; plus per-`(workspaceID, hour-bucket)` span/log counts. **Flush interval: 5s, named constant.** Flush = the D162 UPSERT-adds in one transaction; correct under N replicas by construction (add, never set).
- Flush failure: hot path never blocks; counts retained and retried next tick (bounded — past a stated cap under prolonged outage, oldest buckets drop, logged and counted ops-side). Prometheus ops-only, never reconciled against the ledger.
- End-to-end staleness, stated once: quota crossing honored within ≤ flush(5s) + TTL(30s); revocation within ≤ TTL.
