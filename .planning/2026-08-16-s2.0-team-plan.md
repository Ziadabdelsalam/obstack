- **K3 (workflow structure for S2.1 churn)**: (i) job names are stable identifiers — exactly `web`, `go`, `kind`; branch protection references them; NO later sprint may rename them (rename silently voids required-checks). (ii) one path anchor per job: `web.yml` uses a single `defaults.run.working-directory` (repo root today → `apps/web` after S2.1, one-line diff); `go.yml` anchors on `services/ingest`; `kind.yml` references `demo/agent-app`; no path repeated inline across steps; any cache keys on the one `package-lock.json` path. (iii) all three workflows: `concurrency` group cancelling superseded runs per PR; every third-party action pinned to a released version tag minimum; triggers `pull_request` targeting `master` (kind adds what K5 requires).
- **K4 (T2 skip enforcement mechanism)**: zero skips — run `go test -v`, fail the job on any skip marker in output. Future legitimate skips enter via an allowlist in the workflow (reviewed change), never silently. Allowlist empty today.
- **K5 (T3 trigger policy — decision RULE, not options)**: measure wall-clock. Full kind job ≤ ~6 min → runs on every PR and joins the required set. Longer → label-trigger (`ci:kind`) + push-to-`master` + `workflow_dispatch`, and kind is EXCLUDED from required checks (required = `web` + `go` only — a conditional required check wedges PRs that never trigger it). T3 states the measurement and which branch fired; advisor confirms at merge. S2.2 revisits when stack-on-kind lands its own job.
- **K6 (T1 rider)**: Node pin = an active-LTS major meeting Next 16.3's documented floor (executor reads the vendored Next docs per AGENTS.md, states the exact version); the pin is recorded in T4's README section — it is what S2.1+ inherits.
