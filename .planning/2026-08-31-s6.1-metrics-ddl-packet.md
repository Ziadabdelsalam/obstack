## 0. Frozen query-API contract (stated first — the DDL exists to serve it)

Module: `apps/web/src/server/queries/metrics.ts`, `server-only`, every function takes a `ScopedClickHouse` (D11 idiom, exactly like `overview.ts`).

```ts
export interface MetricCatalogEntry {
  name: string;                       // OTLP metric name = the identity; catalog is DISCOVERED, never fixture-fed
  type: "gauge" | "sum" | "histogram";
  unit: string;                       // as emitted; "" if none
  lastSeen: string;                   // ISO UTC minute
  attrKeys: string[];                 // observed attribute keys -> the groupBy/filter options the UI offers
}
export function listMetricCatalog(ch: ScopedClickHouse): Promise<MetricCatalogEntry[]>;

export type MetricRange = "1h" | "6h" | "24h";     // widths below; extensible at M6 without schema change
export type MetricAgg = "avg" | "min" | "max" | "last" | "sum" | "rate" | "p50" | "p90" | "p95" | "p99";

export interface MetricSeriesQuery {
  metric: string;
  range: MetricRange;
  agg: MetricAgg;                     // validity by type: gauge -> avg|min|max|last; sum -> sum|rate; histogram -> pXX|avg
  groupBy: string | null;             // an observed attribute key ("service.name" included) or null
  filters: Record<string, string>;    // attrKey -> exact value; the fixture's service/env filters are instances of this
}
export interface MetricSeriesPoint { t: string; v: number | null }  // null = empty bucket (honest gap, never 0)
export interface MetricSeries { group: string | null; points: MetricSeriesPoint[] }
export function queryMetricSeries(ch: ScopedClickHouse, q: MetricSeriesQuery): Promise<MetricSeries[]>;
```

Semantics (binding):
- **Bucket widths:** 1h → 1m (60 pts), 6h → 5m (72 pts), 24h → 15m (96 pts). All served from the 1m rollup (Q3).
- **groupBy** returns the **top 10** groups by point count; the UI states "showing top 10 of N" — no synthetic "other" (D13).
- **Invalid agg-for-type is a request error**, not a silent coercion.

Deviations from the fixture, recorded (honesty over parity; mock mode byte-identical per D114): fixed-24-buckets → fixed widths above; `env: "prod"|"staging"` → a `deployment.environment.name` filter like any attribute; `GroupBy = service|model|route` → any observed attr key; the 15-metric catalog → discovered catalog (per the S6.1 fence already ruled).

## 1. Q1 — Schema shape

**Ruling: ONE wide data-points table for all three temperaments, house-style (the `spans` precedent), not per-type tables.** One batcher, one INSERT, one MV chain; per-type tables triple the write path for zero query benefit.

**Metric identity:** `(name, series_hash)` where `series_hash = sipHash64(name ‖ service ‖ sorted point-attribute KV pairs)`, **computed at ingest by `internal/mapping` (D8: computed at ingest, never at query time)**. `type` is constant per series — which is what makes `anyLast(attributes)`/per-type columns in the rollups *exact*, not approximate: aggregation is always per `series_hash`, so cross-type pollution is impossible by construction.

**Temporality: normalized to DELTA at ingest.** Cumulative sums/histograms convert via a per-series cache in mapping (prev value + start_time): first observation of a series emits no row (OTLP conversion semantics — it registers the series only); reset (value < prev, or start_time changed) emits the value as the delta; delta payloads pass through. Rationale: every downstream layer becomes a pure `sum()` — rollups, rate queries, TTL merges — versus per-series window arithmetic at query time that rollups cannot express. Gauges pass through untouched. **Scaling seam, pre-registered:** the delta cache is per-process; production is single-replica ingest today, and scaling ingest horizontally requires workspace-sticky routing before a second replica serves metrics. Recorded, not silent.

**Histograms: explicit-bounds representation** (what OTel SDKs emit by default) — `bounds Array(Float64)` + `bucket_counts Array(UInt64)` (delta-normalized) + sum/count/min/max. Quantiles computed at query time by linear interpolation over the merged bucket arrays (`arrayCumSum` + first-index), in **one** unit-tested SQL helper in the query module. No sketches: nothing in the contract needs mergeable cross-series quantiles that bucket arrays can't give.

**Attribute storage:** `Map(LowCardinality(String), String)` pair, mirroring `spans`/`logs`; `service` materialized first-class from `service.name` (the house rule: what every filter touches is a column).

**Exemplars: OUT for v1.** Traces are first-class one table over; exemplar columns cost every insert and no S6 surface consumes them.

**Raw table DDL sketch** (migration `0005_metrics.sql`, one migration for all objects, idempotent like the house set):

```sql
CREATE TABLE IF NOT EXISTS obstack.metric_points
(
    workspace_id        LowCardinality(String),
    name                LowCardinality(String),
    type                Enum8('gauge' = 1, 'sum' = 2, 'histogram' = 3),
    unit                LowCardinality(String),
    service             LowCardinality(String),
    series_hash         UInt64,                  -- computed by internal/mapping (D8)
    timestamp           DateTime64(9, 'UTC'),
    value               Float64,                 -- gauge value | DELTA for sums | 0 for histograms
    is_monotonic        UInt8,
    bounds              Array(Float64),          -- histograms only; len = len(bucket_counts) - 1
    bucket_counts       Array(UInt64),           -- delta-normalized
    h_sum               Float64,
    h_count             UInt64,
    h_min               Float64,
    h_max               Float64,
    attributes          Map(LowCardinality(String), String),
    resource_attributes Map(LowCardinality(String), String)
)
ENGINE = MergeTree
PARTITION BY toDate(timestamp)
ORDER BY (workspace_id, name, series_hash, timestamp)
TTL toDateTime(timestamp) + INTERVAL 3 DAY;
```

Raw is an implementation buffer (MV source + re-derivation + debugging), **not a product promise** — hence the flat 3-day TTL and no plan-sweep membership (Q4). Every contract read is served by rollups.

## 2. Q2 — Cardinality

**Cap: 25,000 active series per workspace** (active = `last_seen` within the current UTC day). Rationale by sizing: a mid-size k8s cluster on the S6.4 collector leg (kubeletstats + kube-state, ~50 nodes × ~30 pods × ~15 per-container metrics) lands near 20k; SDK/runtime metrics add hundreds. 25k covers that with headroom; a label-explosion bug (user-id in metric attributes) blows through it within minutes, which is the point. Volume at cap is comfortable: 25k series @ 10s export = 2.5k rows/s/ws raw (3-day TTL bounds it), 36M rows/day/ws in the 1m rollup.

**Enforcement — at ingest, D6 posture:** the delta-conversion cache already keys by series, so the per-workspace active-series set is O(1) per point, free. A point creating a **new** series past the cap is dropped and counted; **established series never drop** (deterministic, no flapping). Boot/rollover reconciliation: count from `obstack.metric_series` (below) where `last_seen >= today`.
- New drop reason `ReasonCardinality` in `internal/metrics` + `metering.DropCardinality`, riding the existing 5s flush.
- **pgmigration `0008`**: `dropped_cardinality` column added to `api_key_health` and `api_key_health_windows` (same add-never-set upsert, D162 pattern).
- **Honest UI statement:** connections hub classifies `dropped_cardinality` in `sourceErrors`; explore renders a workspace-level banner when active-series count ≥ cap: "Series limit reached (25,000) — data points for new series are being dropped." Numbers from the health rows and `metric_series`, never estimated.

**Attribute limits:** a data point carrying > 64 attributes is dropped whole with `ReasonMapping` (a partial attr set would corrupt series identity). No per-value truncation — parity with spans/logs, and the series cap is the real guard.

## 3. Q3 — Rollup grain (derived backwards from the contract)

| Contract need | Served by |
|---|---|
| 1h @ 1m, 6h @ 5m, 24h @ 15m buckets | `metric_points_1m` (query-time `toStartOfInterval` + `-Merge`, the `overview.ts` idiom) |
| Catalog + attrKeys + active-series count | `metric_series` |
| M6's 7d/30d SLO windows (known consumer, not speculative — vision §S7) | `metric_points_1h` |

**Three MVs total, all reading `metric_points` directly** (no chained MVs — chaining forces `-MergeState` gymnastics for nothing). `metric_points_1m` sketch; `_1h` is the identical shape with `toStartOfHour`:

```sql
CREATE TABLE IF NOT EXISTS obstack.metric_points_1m
(
    workspace_id  LowCardinality(String),
    name          LowCardinality(String),
    type          Enum8('gauge' = 1, 'sum' = 2, 'histogram' = 3),
    unit          LowCardinality(String),
    service       LowCardinality(String),
    series_hash   UInt64,
    bucket        DateTime('UTC'),
    attributes    SimpleAggregateFunction(anyLast, Map(LowCardinality(String), String)), -- constant per series: exact
    sum_delta     SimpleAggregateFunction(sum, Float64),      -- sum agg; rate = sum_delta / bucket-seconds
    gauge_min     SimpleAggregateFunction(min, Float64),
    gauge_max     SimpleAggregateFunction(max, Float64),
    gauge_avg     AggregateFunction(avg, Float64),
    gauge_last    AggregateFunction(argMax, Float64, DateTime64(9, 'UTC')),
    bounds        SimpleAggregateFunction(anyLast, Array(Float64)),
    hist_counts   AggregateFunction(sumForEach, Array(UInt64)),
    h_sum         SimpleAggregateFunction(sum, Float64),
    h_count       SimpleAggregateFunction(sum, UInt64),
    h_min         SimpleAggregateFunction(min, Float64),
    h_max         SimpleAggregateFunction(max, Float64),
    max_seen_date SimpleAggregateFunction(max, Date)
)
ENGINE = AggregatingMergeTree
ORDER BY (workspace_id, name, series_hash, bucket)
TTL max_seen_date + INTERVAL 90 DAY;

CREATE MATERIALIZED VIEW IF NOT EXISTS obstack.metric_points_1m_mv TO obstack.metric_points_1m AS
SELECT workspace_id, name, type, unit, service, series_hash,
       toStartOfMinute(timestamp) AS bucket,
       anyLast(attributes) AS attributes,
       sum(value) AS sum_delta,
       min(value) AS gauge_min, max(value) AS gauge_max,
       avgState(value) AS gauge_avg, argMaxState(value, timestamp) AS gauge_last,
       anyLast(bounds) AS bounds, sumForEachState(bucket_counts) AS hist_counts,
       sum(h_sum) AS h_sum, sum(h_count) AS h_count, min(h_min) AS h_min, max(h_max) AS h_max,
       max(toDate(timestamp)) AS max_seen_date
FROM obstack.metric_points
GROUP BY workspace_id, name, type, unit, service, series_hash, toStartOfMinute(timestamp);
```

The `trace_summaries` QUERY RULE carries over verbatim: **always `GROUP BY` the series key + bucket with the matching combinators; never FINAL, never a bare SELECT.**

```sql
CREATE TABLE IF NOT EXISTS obstack.metric_series
(
    workspace_id LowCardinality(String),
    name         LowCardinality(String),
    series_hash  UInt64,
    type         Enum8('gauge' = 1, 'sum' = 2, 'histogram' = 3),
    unit         LowCardinality(String),
    service      LowCardinality(String),
    attributes   SimpleAggregateFunction(anyLast, Map(LowCardinality(String), String)),
    first_seen   SimpleAggregateFunction(min, DateTime('UTC')),
    last_seen    SimpleAggregateFunction(max, DateTime('UTC'))
)
ENGINE = AggregatingMergeTree
ORDER BY (workspace_id, name, series_hash)
TTL last_seen + INTERVAL 90 DAY;
-- + metric_series_mv FROM obstack.metric_points, GROUP BY workspace_id, name, series_hash
```

`metric_series` earns its MV three times over: it IS `listMetricCatalog` (no raw scan), the cardinality reconciliation source, and the attrKeys source.

**Insert amplification:** each metrics batch INSERT pays 3 MV aggregations vs the span path's 1 today. Per 10k-row block: 1m MV groups ≈ block-distinct (series×minute), 1h MV and series MV group far smaller — estimate **3–4× CPU on the metrics insert path only**, fully confined to its own batcher (`newBatcher("metric_points", …)` beside spans/logs, same D5 bounds, `Writer.Close` extended to flush it). Spans/logs pay nothing.

## 4. Q4 — TTL / tiering

- `metric_points` (raw): flat **3-day** table TTL. Implementation buffer, not plan-tiered, sweep never touches it.
- `metric_points_1m`, `metric_points_1h`, `metric_series`: **90-day outer TTL in the CREATE** (the 0004 end-state applied at birth — no separate MODIFY migration; 0004 itself is not edited). All three join `retention.go`'s swept-table list **in place** (per-plan lightweight DELETE past `plans.retention_days`, keyed on `max_seen_date`/`last_seen`), preserving the 0004 invariant: a dead sweep degrades to over-delivery, never unbounded growth. `metric_series` is swept so a workspace's catalog forgets series older than its plan's retention — the catalog telling the truth is part of D13.
- **Plan tiers:** metrics retention = the plan's existing `retention_days`, same number as traces/logs. No new plan column, no per-signal tiers — nothing in the product states a different promise.
- **D365 restated as schema fact:** metrics ingestion writes **zero `usage_ledger` rows** and never consults the quota decision — `ReasonQuota` cannot fire on the metrics path. Guards: series cap + accepted/dropped health counters. Billing metrics volume stays the pre-registered USER-VISIBLE pricing decision.

## Amendment D373 (2026-09-01, E-T1 — measured on the pinned engine)

Probe on clickhouse-server 26.3.17.110: `anyLast` over `Map(LowCardinality(String), String)` returns `Map(String, String)` (wrapper stripped), and a `SimpleAggregateFunction` column's storage type must equal the function's return type — the packet's original pairing is structurally rejected (code 36). **Ruled replacement in `metric_points_1m`, `metric_points_1h`, `metric_series`:**

```sql
attributes SimpleAggregateFunction(anyLast, Map(String, String))
```

Grounds: attributes are constant per `series_hash` (they define the series), so `anyLast` is exact either way; the raw table keeps `Map(LowCardinality(String), String)` (where the dictionary earns its keep) — MV SELECTs unchanged (implicit lossless LC→String coercion on insert); `type`/`unit`/`service` are GROUP BY key columns, untouched; T6's contract unaffected. **Re-probe hardening (binding):** for EVERY SimpleAggregateFunction column in the DDL, assert `toTypeName(fn(col))` equals the declared storage type — one run, whole-DDL coverage, escalation class exhausted.

## Amendments D375–D378 (2026-09-01, E-T2 — reviewer escalations accepted as packet defects)

- **D375 (identity = OTLP stream identity):** hash input becomes `sipHash64(name ‖ type ‖ service ‖ sorted KVs of mapUpdate(resource_attrs, point_attrs))` (prefix-free framing retained; point attrs win collisions). Raw table unchanged (both maps, OTLP fidelity); the three MV `attributes` expressions become `anyLast(mapUpdate(resource_attributes, attributes))` so rollup/series attributes carry the merged label set (resource-borne groupBy keys work — k8s.pod.name for S6.4). §2's 25k cap stands, now on a real pod-level basis.
- **D376 (cap admission in the cache):** `NewSeriesCache(cap int)`; admission inside `MetricRows` — unregistered series at cap → row dropped, returned as a cardinality-drop count; established always admitted; a REJECTED series allocates NO cache entry (binding). `Seed(workspaceID, hashes)` loads the active-window set from `metric_series` at boot. Consumer meters the returned counts (ReasonCardinality/DropCardinality) exactly where ReasonMapping counts today.
- **D377 (activity window):** entries carry lastSeen; ActiveCount = lastSeen within current UTC day; idle >24h evicts (memory ≈ ≤2× cap per workspace). Accepted cost on record: a cumulative stream silent >24h re-enters as first-observation (one dropped delta point).
- **D378 (type in identity):** type joins the hash; dual-emission yields two series (no silent merge, no ORDER BY change); `listMetricCatalog` groups by `(name, type)` — two honest entries, never an anyLast(type) pick.

## Amendment D379 (2026-09-01, T5 review escalation)

`metric_series.first_seen` means "first seen within the retention window" — the lightweight sweep's forward-jumping merge on still-active old series is the honest value (a first_seen predating deletable data would be a fact about deleted rows: the D13 inversion). The frozen contract exposes only lastSeen today; if firstSeen is ever surfaced, its label carries this meaning.

## Amendment D380 (2026-09-01, E-T2b — activity clock trust boundary)

The SeriesCache activity clock is **ingest wall-clock, full stop**: entry lastSeen set/touched with server time.Now().UTC() at admission — producer timestamps never drive the window, cap, or eviction (a cap whose clock the sender controls is not a cap). Not min(now, point_ts). Stored `metric_series.last_seen` KEEPS the point timestamp (a fact about the data, D13; D379 retention rides it). Boot Seed keeps reading the stored column; under-seeding for backdated streams degrades safe (re-admits under the cap or pays one first-observation point). Binding test: a stream timestamped before today's UTC midnight still trips the cap.

## Amendments D381–D382 (2026-09-01, T6 review escalations)

- **D381 (§0 shape):** `queryMetricSeries` returns `MetricSeriesResult { series: MetricSeries[]; totalGroups: number }` — truncation statement and truncated data are one answer. totalGroups = pre-truncation distinct-group count; with groupBy null it equals series.length. T7 renders "showing top 10 of {totalGroups}" ONLY when totalGroups > 10 — an untruncated result states nothing. `lib/metrics-types.ts` gains MetricSeriesResult.
- **D382 (accepted limit, pre-registered):** dual-emitted name + type-ambiguous agg resolves to the deterministic ordered-first type; both catalog entries render honestly. `MetricSeriesQuery` gains an explicit `type` field when the first consumer needs disambiguation (S6.3 dashboards / M6 rules) — an additive amendment then, not a speculative field now.

## Amendment D383 (2026-09-01, T4 review escalation — accepted/drop axes)

`accepted` counts records the service took responsibility for after auth+decode (D23); every post-acceptance refusal — mapping, cardinality, write — is a drop under its reason column, a second axis, never a subtraction from accepted. Quota head-sampling shrinks the payload BEFORE responsibility is taken, so those records were never accepted — the boundary case proving the rule. "Stored" = accepted − (mapping + cardinality + write). If reading-against-accepted confuses in practice, the fix is a connections-hub label, not a counting change (pre-registered as UI copy).
