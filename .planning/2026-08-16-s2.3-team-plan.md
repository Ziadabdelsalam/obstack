### Kickoff gate rulings (advisor, 2026-08-16 — BINDING; verdict: wave 1 dispatches on the user's go)

**D44 (Q1 — pagination/totals): (a). Offset/limit pages + an exact count query per request.** The header claims M, so M is computed, per request, from the same filtered predicate as the page — D13/D21 admit nothing else, and (b)'s cursor still needs the count query, so it buys only deep-offset economy M2-scale data cannot feel. Binding shape: (i) **the total is the FILTERED total** — count over the same WHERE/HAVING the page uses (`SELECT count() FROM (<grouped, filtered subquery>)`); the second unfiltered read at `apps/web/src/app/app/traces/page.tsx:43-51` is deleted, not conditioned. (ii) **Deterministic page order**: `ORDER BY min(min_start) DESC, trace_id` — the tie-break is mandatory; offset paging over a tie-unstable sort returns overlapping pages after a merge, which is T1's "page 2 disjoint" probe failing for real. (iii) Page size a named constant; page number in the URL; the D7 GROUP-BY rule (never FINAL, never bare SELECT) applies to the count subquery identically. **Sub-question: `/app/logs` does NOT paginate.** It is a capped window: named cap constant, **cap+1 fetch, single-place slice + explicit truncation marker** — the S2.2 E3 precedent verbatim. Header states rendered count + "more exist" only when proven by the +1 row. Rationale: logs is a narrow-by-filtering surface; the exit asks it to *search*, not to browse; an exact count over log volume is a cost with no exit clause behind it.

**D45 (Q2 — free-text reach + semantics, resolves the PRD tension): (a). One contract, mock's semantics, full reach.** The contract, written in exactly one place (T1 owns the doc location; both implementations cite it):
- **Terms**: whitespace-split, case-insensitive substring, **AND across terms**; a term matches if ANY field in the trace's reach set contains it.
- **Reach set**: summary fields (`root_name`, `trace_id`, `models`, `services`) ∪ span `name` ∪ span `prompt`/`completion` ∪ log `body` ∪ **log `prompt`/`completion`** — all for trace-carrying rows only.
- **Carrier sub-question: D42 carrier rows ARE in the "prompts" reach.** The carrier row is where event-form prompt content physically lives; the UI renders it folded into `LlmDetail` (D42(d)), so search must find what the UI displays — excluding carriers would make every event-form trace unfindable by its own visible prompt, a D13 lie. No conflict with D42(d): that is a **display** rule (carriers don't render as rows); this is **reach** (their content is searchable). The placeholder "Search traces, spans, prompts, logs…" (`TracesSearch.tsx:110`) becomes true as written.
- **Mock matcher corrected to the contract**: `data.ts:64` matches `llm?.prompt` only — it gains completion. A contract with two implementations means the mock moves too, not just live.
- **SQL mechanism**: per term, OR across three legs — summary-field predicates + `trace_id IN (SELECT trace_id FROM obstack.spans WHERE …)` + `trace_id IN (SELECT trace_id FROM obstack.logs WHERE trace_id != '' AND …)`; AND across terms. Dynamic **placeholder-count** generation for N terms is sanctioned; every value stays a bound parameter — generating `{q0:String}…{qN:String}` skeletons is not interpolation, splicing a value is (D11, absolute).

**D46 (Q3 — the skip index): (b). NO index this sprint. The scope fence's "no schema change" is absolute for S2.3 — no 0001/0002 edit is sanctioned.** Two grounds, both falsifiable: (i) **The window argument does not apply to skip indexes.** `ALTER TABLE … ADD INDEX` + `MATERIALIZE INDEX` is additive and online — it rewrites index granules, not data, and is safe on a table holding strangers' rows. ## Retro lessons carried in (binding on done-checks)
- **S2.0 L1 — guards must be proven hollow-proof, not green.** Every assertion in this sprint that claims an **absence** (a filtered-out row, a missing badge, an unrendered carrier) or a **correlation** (free text reached the logs leg; a total came from the data) carries a **falsification probe** shown red-then-green. A search test that passes because nothing was seeded is the same hollow guard as a cached `go test`.
- **S2.1 L1 — lockfile regeneration is a dependency-bump vector.** A pagination control, a date-range picker or a fuzzy-match helper is exactly the temptation here. Any genuinely required npm dependency: stated reason + seeded `--package-lock-only` conversion + diff the version lines. An incidental float is a fence breach.
- **S2.1 L2 — cross-language repo-root literals live outside the tree you are editing.** Route strings (`/app/logs`), column names, env var names and check names also exist in Go, SQL, compose, the chart, the acceptance harness and the docs. Grep **all** trees before calling a change contained.
- **S2.1 L3 — CI runs the exact commands the runbook tells humans to run.** The evidence command in T5 is the human command; no bespoke inline sequence that only CI exercises.
- **S2.2 L1 — a green pipeline is not proof its components are alive.** Where a claim's only proof is a falsification probe, promote the probe to a **standing guard** that asserts data only that mechanism can produce (S2.2's `k8s_node` guard). Applies here to the free-text legs: a query that silently stops reaching log bodies must make something go red.
- **S2.2 L2 — behaviour sized on a warm machine writes a machine-specific number into a ruling.** Any latency number that decides Q3's index — or any timeout — is measured on a stated, seeded dataset with its conditions written down; one warm run is not a bound.
- **S2.2 L3 — a command that inherits hidden state asserts a configuration nobody chose** (measured 3× on Helm v4 upgrades). General form binds here: every scripted or documented command in this sprint (seeding, evidence run) states its fixing values explicitly.
- **S2.2 L4 — literal sweeps are only as good as the file's text-ness.** Separators and sentinels in checked-in sources use escaped forms; a sweep that can silently skip a file is a hollow guard (S2.0 L1 applies to the sweep itself).
