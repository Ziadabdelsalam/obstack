## 8. Post-signature: cluster events (the R3 hand-off closed)

R3 removed every "k8s events" capability sentence because nothing ingested
cluster events (`server/adapters.ts` set `k8sEvents` from no source). The
day after signature the source was built rather than the claim re-worded:

- **Producing half (chart 0.5.0).** A single-replica `obstack-collector-events`
  Deployment runs the `k8s_events` receiver from the same pinned
  `otel/opentelemetry-collector-k8s:0.158.0` image → `batch` → the same
  bearer-key OTLP export to ingest. Deliberately not in the DaemonSet: the
  receiver watches the API server, so per-node copies would ship every event
  once per node. ClusterRole widened with `events` (get/list/watch), gated
  with the workload on `collector.k8sEvents.enabled` (default on; off renders
  byte-identical to 0.4.0 minus comments). `validate` against the real binary
  proved the component exists in the distro (negative control: an unknown
  receiver fails with the valid-values list). No ingest-service change and no
  DDL: event rows are ordinary trace-less `obstack.logs` rows — the receiver
  puts the involved object on the Resource (`k8s.object.kind`/`.name`) and the
  event on the record (`k8s.event.uid`/`.reason`, `k8s.namespace.name`), so
  the promoted `k8s_pod`/`k8s_namespace` columns stay empty and the reading
  side goes through the stored attribute maps. Compose grows no receiver
  (no cluster API) — stated in `config.compose.yaml`.
- **Reading half.** `queryTrace` gains a fifth statement, `K8S_EVENTS_SQL`,
  issued only when the trace's spans carry a `k8s_pod`: trace-less rows with
  `k8s.event.uid`, `k8s.object.kind = 'Pod'`, pair-matched on
  `(namespace, pod)` against the trace's own spans, inside the D37.2 window
  (`W = NEARBY_LOG_WINDOW_S`), `LIMIT 1 BY event_uid` (DaemonSet/count-update
  duplicates), cap 50. `toK8sEvent` maps reason → kind (`OOMKilling`/`OOMKilled`
  → `oom_kill`·fatal; `BackOff`/`Unhealthy`/`Killing` → `restart`; else the new
  `"other"` member — nothing real is dropped; `scale`/`throttle`/`reindex`
  stay story-only since scale events attach to Deployment/HPA objects). The
  key is set only when ≥1 event mapped (the D12 omission pattern). SQL proven
  on a throwaway ClickHouse with the repo's own DDL against seven negative
  cases; +6 adapter tests (515 / 462 pass / 0 fail / 53 skipped).
- **Proof in a cluster (acceptance rider, kind `obstack-s44`, run 1 green,
  456 s).** After D38(e): a third `/chat`, 2 s for the spans to leave the pod,
  `kubectl delete pod` on the serving demo pod, then the harness polls the

  `acceptance:   S4.4 cluster events alive: "Stopping container sidecar" on obstack-demo-57c6575d8f-44wb4 at +1381ms → kind=restart severity=info (2 event(s) on this pod, ±10s of a 25.620541ms trace)`.
