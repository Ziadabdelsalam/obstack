**What went right**:

"Not this sprint's code" was the S8.1 reason; this touchpoint owned the file and still ran once before taking it. A pre-registered fix in a file a task owns is a task item, not an observation.
- **The backups rider's status read assumed a grant** (`SELECT ON system.backups`) instead of reading the statement's own answer — an assumption about the product's user model, found by running the thing (the S7.3 rule, again).

**Lessons carried forward**:
- A pre-registered fix in a file the current task owns is taken at the task's start, not after it strikes.
- A rider reads a status from the statement that produced it before it asks a system table — the product's users hold the grants the product needs, not the ones a test would like.
