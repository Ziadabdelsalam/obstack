- 220 > the 200-row page and 245 > the 200-row cap, so the totals claim is about

- **0 P13-class phantoms.** No span carries an empty `trace_id`, so no
  `trace_id=''` summary row can exist to inflate a total; the "N of M equals the
  independent count" assertion below is therefore also the phantom guard.
- Every number the browser half asserts is passed in from these counts

## 4. Saved views — the D54(iii) coverage of record

D54(iii) designates this run as `SavedViewsMenu`'s **behavioural coverage of
record for S2.3**; there is no DOM harness in the repo and the pinned unit
runner cannot import the component. Driven through the real UI in a real
browser:

- typed a name into the menu's form on `/app/traces?status=error&range=24h` and
  submitted → the view is in the one storage key `obstack.saved-views`;
- the stored envelope carries **no page key** (D47(ii)/D53);
- navigated away to a different URL and re-opened the menu → the view is still
  listed (it is read from storage, not from memory);
- clicked it → URL becomes `/app/traces?status=error&range=24h`, the Status and
  Time range controls hold `error` and `24h`, and the list shows the counted
  `11` error traces.

## 5. Carry-forward 2 and the echo rule, both surfaces (D69, widened by D72)

Traces — the pager is the only control that pushes history (every other control
*replaces*, which is the M1 debounce behaviour), so the sequence runs over a
filtered list:

- deep link `?service=exit-agent` → the input holds it, total is the counted 146;
- pager click → `?range=24h&page=2`, header `20 of 220 traces`, pager `page 2 of 2`, first row differs from page 1;
- `history.back()` → `?range=24h`, `page 1 of 2`, `200 of 220 traces`, range control still `24h`;
- `history.forward()` → `?range=24h&page=2` with the control intact;
- typed service filter → debounced replace to `?service=exit-agent&range=24h`, total 146.

Logs:

- deep link `?sev=error&pod=exit-db-0` → both controls re-synced, exactly the counted 1 row;
- `history.back()` from a searched view → previous filtered view, search box emptied itself, sev/pod restored;
- `history.forward()` → search box refilled, the filters it moved away from cleared;
- **fast double navigation** with 900 ms of injected latency: typed `ab`, let the
  250 ms debounce push it, typed the third character while that navigation was
  still in flight → the box still reads `abc` and the URL settles on
  `/app/logs?q=abc`. Under the single remembered URL this surface shipped
  before F4, the late echo of `ab` rewound the box; the red for that is the unit
  scenario in `use-filter-url-sync.test.ts` (commit `ba650cd`).

## 6. Adversarial URL matrix (D66, D68, D73)

154 requests — `/app/traces` × {q, status, service, model, minMs, minCost,
maxCost, range, page} and `/app/logs` × {q, sev, pod, onTrace, range}, each
against `toString`, `constructor`, `valueOf`, `hasOwnProperty`, `__proto__`,
`1e21`, `99999999999999999999`, `-5`, `NaN`, `%00`, `junk-value` — **all HTTP
200 with the default 6h bound in the header**. This covers the exponential pair
D68 added and the `?minMs=` pair D73 added after F3 found the third 500 of that
class.

The matrix reads the bound byte-wise (`LC_ALL=C`) with an ASCII-only pattern and
carries its own positive control. Both are load-bearing and were measured, not
assumed: `?q=%00` puts a NUL byte in the response, and under a UTF-8 locale a
pattern containing the header's `·` then matches nothing — the check would have
reported a perfectly good page as a missing bound (S2.2 L4, applied to this
harness's own sweep).

## 8. Known deviation, pre-registered (D63)

The CommandPalette ships four trace entries built from `@/mock/stories`. In live
mode their links are dead:

```

/app/traces/b7e2d94a1c8f5e30 -> HTTP 404
/app/traces/c9d4e71f3a2b8c56 -> HTTP 404

```

They fail *honestly* — 404 is "no such trace", not a fabricated one — but they
are shell fiction in live mode. Not S2.3-caused and not fixed here: the clean
fix needs a client-side mode signal the shell deliberately lacks (D21 made the
badge route-based; `dataMode` is server-only). Pre-registered in the widened M3
shell/marketing-fiction item (D60 as widened by D63). Recorded so this bundle
does not overclaim.
