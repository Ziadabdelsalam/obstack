## Kickoff rulings (packet amendments, appended to the packet tail)

- **D490 — delivery decoupled from evaluation (amends D485).** The evaluator only WRITES event rows (`pending`). A second small ticker — the deliverer, 5s cadence (the metering constant) — claims `pending` events with `FOR UPDATE SKIP LOCKED`, attempts delivery (timeout 5s), increments `attempts`, marks `delivered` or (at 3 attempts) `failed`. At-least-once survives any crash point; the pre-registered "redelivery of stuck pending" collapses into the design instead of being deferred; nothing depends on a post-commit callback surviving the process.
- **D491 — event rows carry their delivery target; test notifications ride the real path (amends §4 DDL + D488).** `alert_events` gains `channel_id` (captured at emit time — later rule edits never retro-target old events; FK ON DELETE SET NULL, a null-channel pending event marks `failed`) and `attempts SMALLINT NOT NULL DEFAULT 0`; `rule_id` becomes NULLABLE. `sendTestNotification` = the action inserts a `pending` event with `rule_id NULL`, title "Test notification"; the deliverer treats it identically to a real event — D488's front-door claim is satisfied through the one path, and web never performs egress.
- **D492 — the egress policy is injected config, strict by default (amends D487).** The D487 fences (HTTPS-only, no literal IPs, no private/link-local/loopback/metadata resolution, resolver-pinned) are the DEFAULT policy; compose/CI inject a test policy (`OBSTACK_NOTIFIER_ALLOW_PRIVATE=true` shape) so the drive's local webhook receiver (compose-internal hostname = private range, plain HTTP) is reachable — without this the drive cannot prove delivery at all. A Go test proves the default is strict (env unset ⇒ all three refusals red-proven); production config never sets the escape hatch and the deploy touchpoint verifies its absence.
